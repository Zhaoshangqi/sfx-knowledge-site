# 视频学习流、准确跳转与术语表设计规格

**状态：** 待确认
**日期：** 2026-08-14
**范围：** 视频详情、效果器详情、本站字幕全文、静态 GitHub Pages 发布

## 1. 背景与基线

现有网站已经具备 82 个视频记录、27 个公开效果器档案、站内 YouTube 播放器和本站中文字幕。当前主要问题不是内容不足，而是内容之间缺少稳定的学习路径：

- 视频详情先展示较长的设计说明，播放器出现得较晚。
- 页面没有章节导航，滚动后播放器离开视野。
- 步骤、截图、效果器案例与视频之间只有“打开视频”，不能回到准确位置。
- 效果器档案统计全部用法，但详情只显示少数视觉案例。
- 字幕全文按播放 cue 展示，短句碎片较多，不适合连续阅读。
- 效果器和声音设计术语分散在正文中，没有统一的中英文解释。

本轮审计得到以下数据基线：

- 82 个视频记录。
- 924 个制作步骤，其中 847 个步骤已有截图。
- 684 条效果器用法；27 个公开效果器档案关联 97 条公开案例。
- 27 个档案现有 49 个视觉项，其中 14 个档案包含多个案例。
- 924 个步骤和 97 条公开案例目前都没有结构化准确时间点。
- 字幕 catalog 为 75 条轨道、7 条明确 `missing`，不能声称 82 条视频都有字幕。

因此，“准确跳转”不能只增加按钮。时间点补录、来源复核和全量校验是发布门槛。

## 2. 目标

1. 视频详情首屏就能看到播放器和快速结论。
2. 页面提供稳定章节导航，播放后滚动阅读时播放器保持可见。
3. 每个公开步骤、步骤截图和效果器案例都有经视频复核的准确时间点，并能从任意入口回到该时间。
4. 效果器详情展示该档案关联的全部案例，不再受三张视觉项上限影响。
5. 默认页面只展示快速结论和处理链速览，完整事实与证据仍可展开阅读。
6. 字幕覆盖层继续使用原始 cue；字幕全文改为合并后的完整句段。
7. 建立统一的效果器与声音设计中英文术语表，并在当前视频中只展示相关术语。
8. 保持现有证据边界：不新增练习、不编造参数、不把字幕当作画面证据、不把不匹配截图绑定给效果器。

## 3. 非目标

- 不下载或自托管 YouTube 视频。
- 不依赖 YouTube 官方翻译字幕。
- 不增加账号、打卡、练习、评分、预计学习时间或课程进度。
- 不自动生成未经人工复核的时间点、案例结论或术语定义。
- 不用通用插件官网图冒充某个视频案例截图。
- 不在本轮增加跨视频 A/B 音频、在线效果器模拟或参数预设。

## 4. 设计原则

### 4.1 准确优先

字幕关键词匹配只能帮助定位候选区间，不能直接写入时间点。每个发布的时间点必须回到 YouTube 播放器核对画面或作者操作；无法核对时保持缺失并阻止“全量准确跳转”版本发布。

### 4.2 一个内容事实只有一个来源

步骤时间写在对应 `record.steps[]`。效果器案例优先关联同一个步骤并继承时间和截图；只有案例发生在不同位置时才记录自己的时间。Skill 导出继续读取同一份网站记录，不另建一套互相漂移的案例文案。

### 4.3 快速阅读不等于删减

页面首层只减少同时可见的文字量。原有设计思路、步骤、参数线索、限制、来源和证据标签仍在 DOM 中，以原生 `<details>` 分组保存。

### 4.4 显式表达未知

字幕继续保留 `missing`、`draft`、`reviewed` 等真实状态。截图或时间点无法确认时不使用推断值，也不以相似插件图填补。

## 5. 页面信息架构

### 5.1 视频详情顺序

视频详情调整为以下顺序：

1. 标题、来源、更新时间和分类。
2. 播放器。
3. 快速结论。
4. 章节导航。
5. 处理链速览。
6. 完整制作证据。
7. 效果器用法。
8. 术语表。
9. 字幕全文。
10. 证据边界与来源。

“快速结论”只使用已有可靠字段：

- `summary` 作为一句话结论。
- 最多 3 条完整 `coreIdeas` 作为关键决策，不截断句子。
- 步骤名称和时间点组成处理链速览，不复制步骤长描述。

其余 `coreIdeas`、完整步骤、`chainFocus`、`parameterLogic`、插件信息、tips、限制和来源按主题进入“完整制作证据”，默认折叠。

### 5.2 章节导航

章节导航使用真实锚点，不复制正文：

- `快速结论`
- `处理步骤`
- `效果器用法`
- `术语`
- `字幕`
- `证据与来源`

仅渲染当前记录实际存在的章节。点击后展开必要的父级 `<details>`，再滚动并聚焦章节标题。桌面使用纵向导航；窄屏使用可横向滚动的紧凑标签栏。`IntersectionObserver` 更新当前章节的 `aria-current="location"`，不改变 URL 历史。

### 5.3 播放器前置与悬浮

- 播放器紧跟标题元数据，手机首屏不先经过长段正文。
- 宽度不小于 1040 px 时，详情使用正文与播放器双列布局；播放器列 `position: sticky`，不覆盖正文。
- 640-1039 px 时，播放器在正文上方并在播放激活后吸附到顶部。
- 小于 640 px 时，播放器仍在正文上方；播放激活后可吸附到顶部，最大高度为 `36vh`，并提供图标化的“收起/恢复悬浮”控制。未激活的封面不悬浮。
- 站内全屏继续作用于完整播放器容器，本站字幕随画面进入全屏。
- 悬浮状态不能重建 iframe、重置播放位置或重复创建字幕轮询。
- 播放舞台与字幕全文使用两个挂载点：悬浮区域只包含视频、覆盖字幕、状态和播放控制；字幕全文保留在正文的“字幕”章节，不能跟随播放器一起悬浮。

## 6. 准确时间点数据模型

### 6.1 视频时间线元数据

每个记录新增：

```js
timeline: {
  durationSeconds: 381,
  reviewedAt: "2026-08-14",
  source: "youtube-player"
}
```

`durationSeconds` 来自实际播放器时长；`reviewedAt` 表示本记录全部公开步骤的时间点已逐项核对。没有完整复核时不能写入 `reviewedAt`。

### 6.2 步骤时间点

每个公开步骤新增必填数值字段：

```js
{
  order: 3,
  name: "建立瞬态层",
  startSeconds: 142,
  detail: "...",
  imageKey: "..."
}
```

- 精度到整秒，指向该操作第一次清楚出现的位置。
- 必须满足 `0 <= startSeconds < timeline.durationSeconds`。
- 同一步骤的截图跳转到该步骤的 `startSeconds`。
- 若一个步骤跨越多个片段，只记录最早能够理解该操作的位置；后续独立操作应拆成新步骤。

### 6.3 效果器案例时间点

公开效果器案例继续由 `effectUses` 表达。每条公开案例必须满足：

- 有稳定 `id`。
- 有明确 `stepIndex`，且该步骤标题或证据确实属于该效果器。
- `target`、`purpose`、`result` 能分别回答“用在什么声音上、做了什么、听感变成什么”。
- 默认继承关联步骤的 `startSeconds` 与 `imageKey`。
- 只有效果器实际出现位置与关联步骤不同，才在 `effectUses[]` 写独立 `startSeconds`。
- 独立 `screenshotKey` 仍必须通过现有严格插件名与步骤归属校验。

现有 legacy plugin 投影若进入 27 个公开档案，必须迁移为显式 `effectUses` 并用 `replacesPluginIndexes` 去重。97 条公开案例全部完成迁移后，详情才允许声称“全部案例”。其余未公开 legacy 用法不因本轮自动获得画面确认。

### 6.4 时间点迁移流程

1. 新增只读审计工具，列出每个视频缺失的 `timeline`、步骤时间、公开案例关联和截图归属。
2. 可用本站字幕、步骤名称和截图作为候选定位线索。
3. 在 YouTube 播放器逐项核对候选位置，写入整秒时间。
4. 对 7 条无字幕视频使用完整视频画面手动定位，不从字幕推断。
5. 运行校验器，要求 82/82 timeline、924/924 步骤时间和 97/97 公开案例跳转全部通过。
6. 随机抽检不能替代全量结构校验；浏览器验收另外覆盖每类入口。

若源视频已不可播放，记录阻塞清单并停止发布“全量准确跳转”，由用户决定移除该案例还是保留无跳转状态。不得填入近似时间蒙混通过。

## 7. 路由与播放器控制

### 7.1 可分享深链

现有 hash 参数扩展为：

```text
#video=<recordId>&t=<seconds>&section=<sectionId>&origin=effects
```

- `t` 只接受有限非负数，序列化为整秒。
- `section` 只接受当前章节白名单。
- 无效参数被忽略，不影响原有 `#video`、`#effect`、`#view` 路由。
- 从效果器案例进入视频时保留 `origin=effects`，返回按钮仍回到效果器库。

### 7.2 播放器控制器

`SfxYouTubeCaptionPlayer.mount()` 返回的控制器扩展为：

```js
{
  playAt(seconds),
  seekTo(seconds),
  destroy()
}
```

- 播放器未激活时，`playAt` 保存待播放时间并触发同一套懒加载流程。
- 播放器已就绪时，调用 YouTube `seekTo(seconds, true)` 和 `playVideo()`。
- 页面首次通过深链打开时，因浏览器自动播放限制，封面显示“从 MM:SS 播放”；用户点击后从该位置开始。
- 页面内由用户点击时间按钮触发时可直接尝试播放；若浏览器阻止自动播放，仍保持已定位状态并显示播放封面。
- 每次路由切换仍销毁旧实例，不能出现后台旧音频或旧字幕。

### 7.3 跳转入口

以下入口都显示统一的播放图标和 `MM:SS`：

- 处理链速览中的每个步骤。
- 完整步骤标题。
- 步骤截图上的时间按钮；点击图片本身仍只负责放大或播放 motion 证据。
- 视频详情中的每条效果器用法。
- 效果器详情中的每个案例。
- 合并后的字幕句段。

时间按钮的无障碍名称包含视频、步骤或案例名称和时间。键盘触发与鼠标点击行为一致。

## 8. 效果器详情展示全部案例

### 8.1 档案头部

保留当前经证据约束的三项总览：

- 适用输入。
- 处理动作。
- 听感结果。

同时显示真实覆盖状态，例如：`8 个视频案例 · 8 条用法 · 8/8 已定位 · 6/8 有对应截图`。数字由数据计算，不手写。

### 8.2 全部案例列表

详情主体从 `profile.uses` 渲染一条案例对应一项，不再从最多 3 个 `profile.visuals` 推断案例数量。排序规则为：

1. 绑定总览证据的主案例。
2. 来源视频更新时间倒序。
3. 同一视频内按 `startSeconds` 升序。

每项案例显示：

- 来源视频标题。
- 当前案例的适用输入、处理动作、听感结果。
- 步骤名称和准确时间按钮。
- 该案例严格拥有的截图；没有严格截图时明确显示“本案例暂无对应截图”，不使用官网图代替。
- 证据标签和必要的限制说明。

官方插件图只保留在档案头部的“界面对照”，不能进入视频案例列表。

### 8.3 截图归属

移除 `visuals.length >= 3` 对案例展示的影响，但保留严格归属规则：

- 案例截图必须来自该 `useId` 的 `screenshotKey` 或关联步骤 `imageKey`。
- 步骤标题必须明确识别当前插件产品，通用“EQ”“压缩”等名称不能占有产品截图。
- 一张视频截图不能同时归属两个互斥产品身份。
- 无法通过规则的案例仍显示文字和跳转，但不显示错误图片。

## 9. 快速结论与完整证据

### 9.1 默认展开层

默认可见内容控制在以下范围：

- 一句话结论。
- 最多 3 条关键决策。
- 处理链步骤名称与时间点。
- 效果器用法的简洁“输入 / 动作 / 结果”。

### 9.2 默认折叠层

“完整制作证据”按主题拆为多个原生 `<details>`，避免一个超长折叠块：

- 完整设计思路。
- 逐步制作过程与截图。
- 完整效果链与参数线索。
- 限制、失败尝试与证据边界。
- 来源与更新记录。

章节深链或时间入口可以自动展开目标块。折叠内容仍保留在详情 DOM 和现有站内搜索索引中；打印样式默认展开全部证据。

## 10. 字幕完整句段

### 10.1 双层字幕模型

- 播放器覆盖层继续使用现有短 cue，保持 200 ms 同步和两行显示约束。
- 字幕全文使用由 cue 派生的句段，不修改、覆盖或重新发布原始字幕 JSON。
- `mount(root, { transcriptRoot })` 将完整句段渲染到正文中的独立字幕挂载点；未提供 `transcriptRoot` 时保留当前内部挂载兼容路径，便于单元测试和渐进迁移。

`SfxVideoSubtitles` 新增纯函数：

```js
paragraphsFor(track) => [{
  start: 40.2,
  end: 53.8,
  text: "合并后的完整句段。",
  cueIndexes: [12, 13, 14]
}]
```

### 10.2 合并规则

按顺序合并相邻 cue，并在以下任一条件满足时结束句段：

- 文本以 `。！？!?…` 等句末标点结束。
- 相邻 cue 间隔大于 1.2 秒。
- 合并后持续时间将超过 24 秒。
- 合并后正文将超过 120 个 Unicode 字符。

英文词之间保留一个空格；中文片段不额外插入空格；保留原有标点和词序。算法必须满足：

- 不丢字、不重排、不重复。
- 输入 cue 不被修改。
- 句段时间覆盖其全部成员 cue。
- 点击句段跳到第一个成员 cue 的 `start`。
- 当前播放 cue 对应的句段获得 `aria-current`，但不强制每 200 ms 滚动页面。

## 11. 效果器与声音设计术语表

新增独立、可测试的 `src/sfx-glossary.js`，每条术语为人工维护：

```js
{
  id: "transient",
  english: "Transient",
  chinese: "瞬态",
  aliases: ["attack transient", "瞬态起音"],
  meaning: "声音刚开始、决定轮廓和冲击感的短暂部分。",
  use: "判断打击感、清晰度以及前后层次。"
}
```

首批覆盖网站高频概念和处理类别，包括但不限于：EQ、filter、compression、limiting、saturation、distortion、transient、body、texture、tail、layer、bus、send、return、sidechain、dry/wet、formant、convolution、granular、resonance、automation、pitch 和 stereo width。

展示规则：

- 根据当前记录正文、效果器名称和字幕句段检测别名，只展示当前视频相关术语。
- 术语名称同时显示英文与统一中文译名。
- 解释保持一句“是什么”和一句“什么时候关注”，不加入参数建议。
- 产品名保持官方写法，不擅自翻译。
- 别名匹配使用英文词边界与中文直接匹配，避免 `bus` 命中无关英文单词。
- 当前视频没有匹配术语时不显示空章节。

术语表本身不改写字幕原文；它只提供旁路解释，避免字幕术语校对与正文展示互相污染。

## 12. 失败与降级行为

- YouTube API 加载失败：保留现有错误提示和原视频链接，正文与截图仍可阅读。
- 字幕轨加载失败：视频和所有结构化时间跳转继续可用，字幕状态单独报错。
- `missing` 字幕：不显示字幕全文和术语的字幕命中，只使用记录正文检测术语。
- 时间参数无效：忽略 `t`，播放器从正常封面开始。
- 目标章节不存在：打开视频顶部，不渲染空章节。
- 截图缺失或归属校验失败：案例保留文字和时间跳转，图片区域显示真实缺失状态。
- 打开折叠章节时禁用平滑滚动偏好必须尊重 `prefers-reduced-motion`。

## 13. 测试与发布门槛

### 13.1 数据契约

- 82/82 记录具有合法 `timeline` 和 `reviewedAt`。
- 924/924 公开步骤具有合法 `startSeconds`，且小于视频时长。
- 847/847 已声明步骤截图仍解析到真实 preview/full 资产。
- 27/27 公开效果器档案可解析。
- 97/97 公开效果器案例具有稳定 ID、明确步骤、准确时间和简洁三段描述。
- 公开案例数等于详情渲染案例数；不能以视觉项数量代替案例数。
- 截图归属、唯一所有权和通用名拒绝规则继续通过。
- 字幕覆盖继续如实报告 75 track + 7 missing，除非本轮实际新增并审校轨道。

### 13.2 单元与集成测试

- hash 路由解析、序列化、非法 `t`/`section` 降级和返回来源。
- 播放器就绪前、就绪后、API 失败和销毁后的 `playAt`/`seekTo`。
- 章节导航只渲染存在章节，并能展开折叠父级。
- 快速结论可见、完整证据默认折叠、正文不丢失。
- 全部效果器案例渲染、排序、计数和严格截图归属。
- 字幕句段按标点、间隔、时长和长度结束；文本无损；点击可 seek。
- 术语别名、词边界、中文匹配、去重、排序和不可变数据。
- 原有播放器字幕覆盖层、CC、全屏、轮询和销毁测试不得回归。

### 13.3 浏览器验收

至少在 1440x900、1024x768、390x844 和 844x390 验收：

- 首屏播放器位置和快速结论层级。
- 悬浮播放器不遮挡标题、章节导航、字幕或正文。
- 收起/恢复悬浮不重置视频。
- 从步骤、截图、效果器案例和字幕句段跳到已知时间。
- 从效果器详情跨路由进入视频，并能返回效果器库。
- 深链刷新后保留目标时间和章节。
- 折叠内容可键盘操作，当前章节与当前字幕句段状态正确。
- 无横向溢出、文字重叠、错误图片、控制按钮尺寸跳动和控制台错误。

### 13.4 完整验证

继续运行仓库现有 Node、Python、portable-kit、语法和 `git diff --check` 全量验证。数据变更后重新导出并核对 `sfx-knowledge` Skill 记忆，确保网站与 Skill 使用同一份案例与证据边界。

## 14. 实施顺序

1. 先写时间、案例、字幕句段、术语和路由的失败测试。
2. 实现不依赖内容迁移的纯数据模块与播放器控制器。
3. 完成 82 个视频的 timeline 和 924 个步骤时间点复核。
4. 将 97 条公开效果器案例迁移为显式、可定位的 `effectUses`。
5. 实现视频详情与效果器详情新结构。
6. 完成桌面、平板、手机和全屏验收。
7. 更新 Skill 记忆、提交、推送并等待 GitHub Pages 公开部署验证。

任何阶段都不得用自动推断时间或弱匹配截图换取测试通过。

## 15. 后续可优化但不进入首轮

这些方向有价值，但不应阻塞本轮学习流改造：

- **同效果器跨视频对比：** 以输入类型或目标听感并排比较全部案例。
- **证据覆盖筛选：** 只看有视频截图、已校对字幕或有明确限制说明的内容。
- **字幕与术语联合搜索：** 搜索术语后直接列出所有相关句段和案例时间点。
- **可打印学习摘要：** 打印时自动展开完整证据，生成无交互的一页式记录。
- **内容质量看板：** 在维护端统计时间点、截图、字幕审校和案例描述覆盖率，不在学习页面制造进度压力。
- **本地最近阅读位置：** 只在浏览器本地保存最后视频和章节，不引入账号或学习打卡。

优先级建议是：先完成本规格，再做“同效果器跨视频对比”和“字幕与术语联合搜索”。它们依赖本轮建立的准确时间、完整案例和术语数据，提前做会重复返工。

## 16. 方案结论

采用“结构化时间点 + 单一内容来源 + 播放器控制器 + 双层字幕 + 当前视频术语表”的方案。它比客户端关键词猜时间或单独维护第二份案例目录更慢，但能够满足网站当前最重要的可信度要求，并为后续跨视频比较和搜索建立可复用的数据基础。
