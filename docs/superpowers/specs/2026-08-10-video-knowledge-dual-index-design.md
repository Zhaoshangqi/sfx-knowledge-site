# 视频干货双索引改造设计

## 状态

- 设计方向：已获用户口头批准。
- 当前阶段：先实现一个可验证的试用版本，再决定是否继续逐条深度补录全部历史内容。
- 核心约束：网站用于完整整理视频中的设计思路和效果器用法，不提供练习、打卡或课程任务。

## 背景

当前网站已经有 82 条独立视频记录，并保留了步骤截图、插件、参数、材料、效果链和证据边界。现有内容量足够，但详情页仍带有明显的课程化结构：`practiceChecklist` 被渲染为“练习复盘”，部分 `chainFocus`、`parameterLogic` 和步骤文本也包含“复刻、练习、弱中强三版”等话术。

用户实际需要的是专业参考档案：先理解作者如何拆解声音问题，再查清楚效果器放在哪里、为什么使用、怎么调、产生了什么变化。用户提供的飞书脑图也采用“效果器或脚本名称 + 具体作用 + 参数或替代用法 + 界面截图”的记录方式，例如 Vocoder 频段数量、RX De-click 的非常规使用、H3000 的音高与运动塑形、SplitEQ 的谐波/非谐波拆分等。

因此本次改造不继续强化练习路线，而是把现有知识改造成两个互相链接的入口：完整视频案例和跨视频效果器索引。

## 目标

1. 让读者先看懂一条视频解决了什么声音问题，以及作者的完整设计思路。
2. 完整保留视频中的素材选择、分层、步骤、效果链、参数、路由、自动化和关键决策。
3. 提供跨视频效果器索引，同一效果器的不同用途可以被并列查找。
4. 从界面和搜索中移除练习、打卡、难度和预计学习时间等课程化信息。
5. 保留现有证据标准，不把字幕、推断或未显示参数写成已确认事实。
6. 在不破坏 82 条历史记录的前提下先交付试用版本，后续再逐条补齐更细的结构化字段。

## 非目标

- 不删除或重做原始截图、视频来源和历史分析证据。
- 不在试用阶段人工重写全部 82 条记录。
- 不把整段字幕直接搬进页面，也不把寒暄、宣传和重复表达当作干货。
- 不根据插件品牌或相邻视频猜测未展示的参数、路由、听感或作者意图。
- 不加入测验、练习清单、学习进度、收藏同步或账户系统。
- 不改变 GitHub Pages 的纯静态发布方式。

## 方案选择

### 方案 A：只按视频整理

优点是完整保留制作上下文，实现成本最低。缺点是同一个效果器散落在多条视频中，无法快速比较不同用途。

### 方案 B：视频案例与效果器索引共用一份数据

视频页保留完整上下文，效果器页把每次实际使用作为独立条目，并链接回原视频、步骤和时间戳。优点是同时满足“学习设计思路”和“查询效果器用法”，且不会复制两套内容。缺点是需要兼容旧数据并逐步补录更细字段。

### 方案 C：改成纯效果器百科

优点是查插件最快。缺点是会割裂完整效果链，读者很难理解作者为什么在这个素材、这个位置使用该处理。

采用方案 B。

## 信息架构

网站保留单页静态应用形式，顶部增加两个清晰的主视图：

1. `视频案例`：按现有分类、关键词和来源浏览 82 条视频。
2. `效果器索引`：按处理类型、效果器名称和视频来源浏览实际用法。

两个视图共用搜索输入和同一份 `records` 数据。效果器索引中的每个用法必须能回到对应视频详情；视频详情中的每个效果器也能进入索引查看其他案例。

现有视频分类标签继续服务于“视频案例”，不与新的主视图混在同一级。移动端使用紧凑的分段控制切换主视图，不增加新的侧边导航层级。

## 视频详情结构

详情页按下面顺序显示，避免现有内容前后重复：

1. **设计目标**：来自 `summary`，说明视频要解决的声音问题和目标结果。
2. **设计思路**：合并 `coreIdeas` 与 `chainFocus`，只删除规范化后完全相同的句子，先讲拆解逻辑，再讲插件名称。不得用语义摘要替代原文细节。
3. **素材与分层**：来自 `materials`，明确 transient、body、texture、movement、tail、loop、UI feedback 等职责；没有证据时只显示原有材料描述。
4. **完整制作流程**：按 `steps` 原顺序展示动作、细节、参数、截图和时间信息。
5. **完整效果链**：展示已确认的顺序、串并联、轨道/总线位置、自动化和上下游因果；无法确认时明确标注。
6. **效果器用法**：每个插件或处理点使用统一的信息结构，链接到跨视频索引。
7. **关键决策与证据边界**：保留作者说明、画面事实、分析推断、未展示项和使用限制。
8. **来源与关键词**：原视频链接、来源频道和检索标签放在页尾。

不再渲染“练习复盘”。`practiceChecklist` 也不参与站内搜索或效果器索引。试用阶段先保留底层历史字段，避免无必要的数据破坏；后续生成器停止新增该字段。

部分历史字段把真实参数和课程模板写在同一个字符串里，例如“参数逻辑：Dry/Wet 约 63%。复刻时只调一个核心旋钮……”。展示层只能裁掉已知的模板尾句，保留前面的参数事实。不得按“练习”“复刻”等单个关键词删除整段，也不得对普通视频原话做自动改写。

## 效果器用法模型

新记录可选用 `effectUses` 字段保存结构化用法：

```js
{
  id: "record-id:effect-slug:1",
  name: "Polyverse Manipulator",
  vendor: "Polyverse Music",
  category: "音高 / Formant / 频移",
  target: "爆炸主体层",
  chainPosition: "打印变体前，Shade 之前",
  purpose: "改变音高与 formant，同时保留原始冲击重量",
  parameters: [
    {
      name: "Dry/Wet",
      value: "约 63%",
      direction: "保留部分干声",
      evidence: "画面确认"
    }
  ],
  result: "产生非自然的大型怪异感，但仍能听出 boom 的物理主体",
  interactions: "与后续 Shade 一起打印多个身份变体",
  limitations: "该数值只属于视频当前素材，不作为通用预设",
  timestamp: "",
  stepIndex: 0,
  screenshotKey: "",
  evidence: ["画面确认", "作者口述"]
}
```

试用版本必须兼容当前 `plugins`：

- `plugins[].name` 映射为效果器名称。
- `plugins[].purpose` 映射为设计目的。
- `plugins[].settings` 映射为参数与调节线索，但不自动拆成伪精确数值。
- 相关步骤、截图和效果链只在能通过现有字段稳定关联时显示。
- 新模型没有的信息显示“视频未展示”或直接省略，不生成猜测性文字。

后续逐条复核视频时优先补 `effectUses`；旧 `plugins` 字段继续作为兼容输入，直到全部历史记录完成迁移。

## 效果器分类

索引采用功能分类，不以品牌作为一级分类：

- 频谱与音色：EQ、滤波、SplitEQ、共振处理。
- 动态与响度：压缩、侧链、限制、clip、响度增强。
- 饱和与失真：saturation、distortion、exciter、谐波增强。
- 音高与频率：pitch、formant、vocoder、frequency shift。
- 调制与运动：phaser、flanger、chorus、tremolo、Doppler、stereo motion。
- 空间与时间：reverb、delay、echo、granular、convolution。
- 修复与非常规处理：RX 修复模块及其创造性用法。
- 自动化、脚本与路由：REAPER 脚本、包络、串并联和中间件控制。
- 未分类：证据不足或用途跨越多个类别时的保守回退。

分类来自结构化字段或明确用途描述。仅凭插件品牌不得推断分类。

## 效果器索引界面

效果器索引使用适合扫描的紧凑列表，不做大量装饰性卡片。每一行显示：

- 效果器名称与厂商。
- 功能分类。
- 本次处理对象与目的。
- 已确认的关键参数或调节方向。
- 来源视频与步骤位置。
- 证据状态。

点击一行后打开独立详情区域，展示完整用法、上下游关系、截图、限制和返回视频的入口。同一效果器按实际用法分组，而不是把多条视频的结论拼成一个没有来源的通用说明。

筛选项包括功能分类、效果器名称、视频来源和证据状态。搜索覆盖效果器名、厂商、用途、参数、目标素材、视频标题和关键词。

## 证据模型

页面统一使用以下标记：

- `画面确认`：界面、参数、路由或步骤在可读画面中出现。
- `作者口述`：作者明确说明用途、选择或结果。
- `音频可辨`：只有在获得完整音频并实际完成监听或分析时使用。
- `分析推断`：基于画面与上下文的可解释推断，不冒充作者结论。
- `视频未展示`：视频没有给出参数、路由、导出或游戏内结果。

同一条目可以有多个来源标签。无法获得完整音频时，不得新增分析者自己的主观听感、响度、频谱或动态结论；作者口述的听感仍可显示，但必须标为 `作者口述`。

## “完整干货”的边界

必须保留：

- 声音目标和约束。
- 素材来源与每层职责。
- 操作顺序和效果链顺序。
- 插件、脚本、路由、自动化和中间件行为。
- 可读参数值、参数变化方向和预设名称。
- 处理前后变化及其证据来源。
- 作者的选择理由、失败尝试、替代方法和限制。
- 关键时间戳与支持结论的截图。

可以删除：

- 寒暄、宣传、订阅提醒和重复复述。
- 与声音设计无关的闲聊。
- 没有新增信息的逐字字幕。
- 为网站额外生成的练习、作业和打卡话术。

## 兼容与迁移策略

试用版本采用非破坏式迁移：

1. 保留 82 条原始记录和现有字段。
2. 在渲染层增加兼容适配器，把 `plugins` 转为只读效果器用法条目。
3. 从详情页和搜索索引中移除 `practiceChecklist`。
4. 对现有 `coreIdeas`、`chainFocus` 和 `parameterLogic` 只做完全重复项去重，并裁掉已知生成模板尾句，不批量改写原始证据文本。
5. 优先用 Vocoder、Manipulator、H3000 等已有明确参数和用途的记录验证效果器索引，并至少补录三条结构化 `effectUses` 示例。
6. 试用通过后，再逐条把重点视频补录为 `effectUses`，并清理仍残留的课程化措辞。

若旧记录缺少效果器信息，视频页仍能正常显示，效果器索引不会生成空条目。若截图丢失，保留文字证据并显示现有资源缺失状态，不用无关图片替代。

## 视觉与交互约束

- 延续当前网站视觉语言，不重做品牌风格。
- 主视图切换使用分段控制；筛选使用下拉菜单或标签，不用大按钮堆叠。
- 视频详情保持单一阅读流，不在正文中嵌套多层卡片。
- 效果器列表在桌面端支持快速扫描，在移动端改为单列但保留完整名称和来源。
- 长参数和限制可以逐条展开，但默认摘要必须能说明“处理谁、为什么、怎么调”。
- 所有图标按钮提供可访问名称和悬停提示；键盘可以完成视图切换、筛选和返回视频。
- 360 px、768 px、1440 px 视口下不出现文字覆盖、横向溢出或固定控件跳动。

## 搜索与数据流

页面加载时从 `records` 构造两套只读索引：

1. 视频索引：标题、摘要、设计思路、材料、步骤、插件、效果链、参数和关键词。
2. 效果器索引：标准化名称、别名、厂商、功能分类、用途、参数、处理对象、来源视频和证据状态。

`practiceChecklist` 不进入任何搜索文本。视图切换只改变结果投影，不复制数据，也不改变 URL 中现有视频定位能力。效果器条目需要可序列化的稳定 ID，确保刷新和深链后仍能定位。

## 试用版本范围

第一版交付以下能力：

1. 新增“视频案例 / 效果器索引”双入口。
2. 调整视频详情阅读顺序并隐藏练习区。
3. 用现有 `plugins` 数据生成跨视频效果器索引。
4. 支持效果器搜索、功能筛选、来源视频回链和证据展示。
5. 为 Vocoder、Manipulator、H3000 相关记录各补充至少一条结构化 `effectUses` 示例，验证新模型能够表达参数、链路位置和限制。
6. 保持原有 82 条记录、视频 ID、图片和 Skill 导出可用。

本阶段不承诺一次性人工重写所有历史文本。试用验收后，再决定完整迁移的批次和优先顺序。

## 测试与验收

### 内容验收

- 视频总数仍为 82，唯一视频 ID 数仍为 82。
- 页面不再显示“练习复盘”，搜索“练习”不会因为 `practiceChecklist` 返回记录。
- 每条视频仍能打开原视频、查看步骤和已存在的截图。
- Vocoder、Manipulator、H3000 等已有记录可以在效果器索引中被找到，并回到正确视频。
- 效果器条目不显示来源数据中不存在的精确参数、听感或路由。
- 同一效果器的多条使用案例保持各自来源，不合并成无出处结论。

### 交互验收

- 主视图切换、搜索、筛选、打开效果器详情和返回视频均可用。
- URL 深链能恢复视频详情和效果器详情；两类详情都使用稳定 ID，并为无效 ID 提供明确空状态。
- 无结果、缺少截图和旧记录缺少插件字段时均有明确空状态，不抛出脚本错误。

### 视觉验收

- 桌面和移动端正文无重叠、溢出、破图和按钮尺寸跳动。
- 效果器列表在常见视口下能读到名称、用途和来源，不依赖悬停才能理解。
- 详情页首屏优先显示设计目标和设计思路，不被大面积元数据或装饰占据。

### 工程验收

- 现有 Node 和 Python 测试全部通过。
- 增加针对双索引、练习字段排除、稳定效果器 ID 和回链的自动检查。
- `node tools/export-site-memory.cjs` 与 `node tools/verify-portable-kit.cjs` 通过。
- Git 变更不包含 `.work`、浏览器凭据、原视频或完整音轨。

## 风险与处理

- **历史文本重复**：先在展示层去重；只有复核过视频证据后才改原始内容。
- **效果器名称不统一**：复用现有插件参考别名，生成标准名称时保留原始名称和来源。
- **自动分类错误**：无法高置信分类时进入“未分类”，不根据品牌猜测。
- **缺少参数或时间戳**：明确省略或标记“视频未展示”，不补模板化参数。
- **索引条目过多**：默认按效果器名称聚合，具体视频用法在详情中展开；移动端维持单列扫描。
- **试用范围膨胀**：第一版只验证结构和少量高质量示例，完整人工迁移另行分批。

## 完成定义

当双入口、去练习化详情、效果器索引、视频回链、证据标记和自动验收均通过，并且 82 条历史记录及发布流程保持可用时，试用版本完成。完整内容迁移只有在用户验收试用版并批准下一批次后才开始。
